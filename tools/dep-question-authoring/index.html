VARIANT MANAGEMENT REFERENCE

Variant Management ガイド

Variant relationの確認・変更で迷ったときに参照する補助情報です。必要な項目だけ開いてください。

はじめて使う方へ — Quick Start
  1. QUESTION CATALOG でQuestionを検索し、内容とrelationを確認します。
  2. 目的に合わせて Create Question / Edit Question / Clone Question / Create Variant を選びます。
  3. Preview / Review でworking Questionをread-only確認します。
  4. Global Validation がPASSしたら、Reviewを開いたままでも Export questions.json でworking Questionsを出力できます。
  5. 出力結果をdep-quiz-app/questions.jsonへ反映し、Git diffとPRを最終確認の正本としてレビューします。

Variant relationを確認・変更する場合だけVARIANT MANAGEMENTへ進み、必要に応じてCandidate Assist / MEMBER COMPARISON & EDIT / SELECTION INSPECTORを使います。

用語解説
Create Question / Edit Question
独立した新規Questionを作る / 選択中の既存Questionを更新する操作です。
Clone Question / Create Variant
Cloneは内容を複製してrelationを継承しない独立Questionを作ります。Create Variantは同じchoice setを固定し、既存または新規Variant Groupへ新しい問い方を追加します。
Preview / Review
working Question、sourceとの差分、Global Validationを確認するread-only工程です。learnerの回答や進捗を再現する画面ではありません。
Candidate Assist / Variant Management
Candidate Assistは同じchoice setを持つ既存Question候補を探すだけで、新規Questionは作りません。Variant ManagementではGroup memberの比較・relation編集を行います。
Selection Inspector
保存を行わず、Variant Groupの代表選択条件を試す確認機能です。
Global Validation / Export
canonical validatorが唯一のquality判定です。選択Questionのrelated errorが0件でもGlobal FAILならExportできず、Global PASSのworking QuestionsだけをExportできます。
バリアント問題
同じ選択肢を使い、問い方を変えた問題です。
Variant Group
同じ知識・判断基準を異なる問い方で確認する問題のまとまり。新規sessionでは、同じVariant Groupから最大1問を代表として採用します。
followUp
元問題の解説後に、理解をもう一段確認するための追加確認候補。元問題から別questionへの1段の参照であり、自動遷移そのものを意味しません。
エラー対策

未保存draft・Reset・Export後の確認

入力中のdraftはsubmitするまでworking Questionsへ入りません。別の操作へ進む際のdiscard確認でキャンセルすればdraftを維持し、破棄を選べばworking Questionsを変えずに移動します。

Reset editsはbrowser memory上の未export編集をsource snapshotへ戻し、開いていたReviewやderived selectionも安全に再調整します。localStorageへのdraft保存やautosaveは行いません。

Validation FAILではerror detailsとReviewを確認して編集へ戻り、Global PASSへ回復してからExportします。Export後はGit diff / PRで意図しない変更やtransient stateの混入がないことを最終確認してください。

同じchoice text multisetではない

Variant Groupは、選択肢本文が一致している必要があります。

対策

Variant Groupとして扱いたい場合
同じ選択肢で、別の問題文（問い方）を作成してください。
Variant Groupではなく類似問題としたい場合
tagsで集約することを検討してください。
1. CREATE VARIANT GROUP

新しい group を作る場合のみ使用します。検索対象は variantGroup 未所属の questions だけで、2問以上の選択が必要です。

Variant Groupにまとめる条件

  • ✓ 同じ知識・判断基準
  • ✓ 問い方・視点は異なる
  • ✓ 選択肢本文は同じ

choice-set一致は必要条件です。最終的に「同じ知識・判断基準か」を確認してください。類似問題だけならVariant Groupではなくtagsでの集約を検討してください。
