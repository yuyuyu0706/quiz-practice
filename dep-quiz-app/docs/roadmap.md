# dep-quiz-app 開発ロードマップ

## この文書の目的と適用範囲

この文書は、`dep-quiz-app` の全体像、現行の Phase 構成、Phase 間の依存順、開始ゲート、および現在有効なロードマップ判断の正本です。個々の Phase の期限や日々の実装進捗ではなく、開発テーマをどの順序で進めるかを俯瞰するために使用します。

対象は Phase D〜G の位置付けと、それらを接続する依存関係です。各機能の仕様、実装手順、進捗、期限、ならびに過去の比較案や長い議論は、それぞれの管理先を参照してください。

## 依存順と開始ゲート

G-1 を完了してから Phase E の残作業と統合確認を進め、`variantGroup` / `followUp` の保留判断を確定した後に Phase F の起票を判断します。Phase F 内は F-1、F-2、F-3 の順に進め、Phase G のうち G-2 / G-3 はその後続とします。

```text
G-1 ルーティング契約・ブラウザ履歴同期 完了
  → #374 完了
  → #318 で Phase E 全体を統合確認
  → variantGroup / followUp の保留判断確定
  → Phase F 起票判断
  → F-1 共通 schema 拡張
  → F-2 バリアント出題
  → F-3 深堀りクイズ
  → G-2 グローバルナビゲーション再設計
  → G-3 個別画面 UI 洗練
```

G-1 は、ブラウザやスマートフォンの戻る・進む操作をアプリ内の画面遷移と同期し、後続機能と E2E の安定した入口を作るため、#374 と Phase E の統合確認より先に完了させます。その後、Phase E の統合結果と G-1 の公開契約を踏まえて二つの保留判断を確定し、Phase F の起票可否を判断します。G-2 / G-3 は Phase F で追加される要素を含めてナビゲーションと画面全体を調整するため、F-3 の後に進めます。

### Phase F の起票判断ゲート

Phase F の親 Issue および F-1 / F-2 / F-3 は、次の 4 条件がすべて成立した後に起票を判断します。

1. G-1「ルーティング契約・ブラウザ履歴同期」が完了している。
2. [Issue #374](https://github.com/yuyuyu0706/quiz-practice/issues/374) が完了し、[Issue #318](https://github.com/yuyuyu0706/quiz-practice/issues/318) で Phase E 全体の統合確認が完了している。
3. 同一 `variantGroup` のセッション内出題制御が確定している。
4. `followUp` による深堀りクイズの提示条件が確定している。

ゲート成立は自動的な実装開始を意味しません。成立時点の `main`、Phase E の成果、G-1 の公開契約を確認し、Phase F の Issue 粒度と実装計画を設計します。

## Phase F 内部の役割

以下はゲート成立後に具体化する責務境界です。

| サブフェーズ | 役割                                                                                                                    | 依存                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| F-1          | `questions.json` と schema / validator を、既存問題との後方互換を維持しながら `variantGroup` と `followUp` に対応させる | Phase E 統合確認、G-1 完了、ゲート条件の確定 |
| F-2          | 問題集合の選択、バリアントを含む session 生成、中断・再開を実装する                                                     | F-1 の公開契約確定後                         |
| F-3          | 解説内の深堀り UI、提示条件、アクセシビリティを実装する                                                                 | F-2 完了後、かつ提示条件確定後               |

バリアントごとに別 question ID を持たせ、既存 progress を壊さない方針です。深堀りクイズは新しい view を増やさず、解説エリア内に展開します。詳細仕様はゲート成立後に各 Issue で定義します。

## 現在保留している判断

次の項目は未確定であり、この文書では結論を先取りしません。

- Phase F の親 Issue および F-1 / F-2 / F-3 の起票は、4 条件のゲート成立まで保留する。
- Phase F の開始日、期限、初期コンテンツ対象数は固定せず、ゲート成立後に [Phase F Milestone](https://github.com/yuyuyu0706/quiz-practice/milestone/5) で確定または再設定する。
- 同一 `variantGroup` の問題を 1 session 内でどのように出題するかは、Phase F 着手前に確定する。
- `followUp` を誤答時、復習推奨時、または利用者の任意操作で提示するかは、Phase F 着手前に確定する。

## 更新ルール

- Phase 構成、依存順、開始ゲート、または現在有効なロードマップ判断を変更するときは、この文書を更新する。
- 変更理由、比較した案、廃止した案、議論の経緯は [Issue #377](https://github.com/yuyuyu0706/quiz-practice/issues/377) に記録し、この文書には採用した現在方針だけを反映する。
- Phase の現在状態、期限、完了条件は対象 Milestone Description で更新し、この文書へ複製しない。
- Phase 内部の実装計画や進捗は対象の Lv1 / Lv2 Issue で更新し、この文書へ日々の進捗を追記しない。
- Project #3 は正本の情報を一覧表示するダッシュボードとして同期し、Project だけでロードマップ判断を確定しない。
- 更新時は README からの導線、関連リンク、Phase 名、依存順、開始ゲートが相互に矛盾していないことを確認する。
